# 指增因子平台 · 功能文档

> 依据：30 轮实测（232 个因子、23 次提交、780 个窗口存档）沉淀的完整能力地图。
> 用途：当作平台的功能参考手册，也当作"一个策略研究平台应该具备什么"的对照表。

## 一、概览

| 项 | 内容 |
|---|---|
| 定位 | A 股指数增强（指增）因子挖掘、评估、入库平台 |
| 入口 | `http://192.168.200.16:9999`（走 VPN） |
| 认证 | Bearer token，存于 `_work/token.txt` |
| 核心产出 | 能入库的因子（正式库），以及每个因子的完整回测账本 |
| 并发 | 回测 ≤ **30 条/波**；admit ≤ **4** |
| 计费 | 回测不烧钱，只烧算力；入库奖金口径 300，效果好 1000 |

## 二、数据层

### 2.1 字段规模

- 共 **279 个字段，24 组**。
- 可用：价量 12 / 五分钟收盘价 49（`$m5_close_0930…1500`）/ 半小时成交额 18 / 分钟衍生 5（`$min_ret_skew/kurt/std`、`$min_up_vol/down_vol`）/ 资金流分档 18 / 高频预计算 9 / 财务 130+ / 估值 7 / 两融 8 / 指数 5 / 行业 / 股东人数 / 龙虎榜。
- **不可用**：Tick 聚合 `$tick_auction_*`（2022-02 才开始，覆盖不了 2017）。

### 2.2 股票池

只有 4 个：`csi2000` / `zz1000` / `zz500` / `hs300`。

## 三、因子层

### 3.1 两种因子形态

| 形态 | 特点 | 相似度可算性 |
|---|---|---|
| **表达式因子** | 平台 DSL 写，`values_in_db=0` | 要等 `evaluation/similarity` 任务算完才落库 |
| **Python 因子**（`#%%python_factor`） | 自己写 `build_factor(ctx)` | 建好 `values_in_db=1`，**可立刻本地算相似度** |

**推论**：值得优先用 Python 实现"必须先验相似度再决定要不要花回测"的新机制。

### 3.2 因子属性

- `name`、`expression`、`direction`（方向）、`meaning`（含义/机制解释）。
- 同一机制可以有多个实现（表达式 / Python），但**因子身份按值算，不按代码算**。

## 四、回测层

### 4.1 网格（必须全扫）

```
变体 factor_variant : raw / ma10 / ma20 / cap_neu           (4)
策略 strategy       : 分行业(idx_industry) / 5桶(idx_sb5)   (2)
   └ 5桶 top_pct    : 10 / 20（由 top20_top_pct 控制）        (2，仅 sb5)
持有期 hold         : 1 / 5 / 10 / 20                         (4)
                   → 合计 4 × (4 + 8) = 48 条 / 因子
```

**为什么必须全扫**：#766 量价相关性在 29 条配置里**只有 1 条**双窗优秀（`ma20 + 分行业 + 持有5日`）；拿 `5桶10日raw` 判它"废"是错的。

### 4.2 成本与口径

- 单边费 **10bp**。
- `rebalance_horizon` **必须 10**（设 20 → 分层单调全 fail）。
- 池：`csi2000 / zz1000 / zz500 / hs300`。

### 4.3 变体的作用

- `raw`：原始因子值。
- `ma10` / `ma20`：对因子做 10/20 日平滑（慢因子常用）。
- `cap_neu`：市值中性化（压回撤，但超额常腰斩）。
- **ICIR 由变体决定**，与策略/持有期无关。

## 五、评估层

### 5.1 指标

| 指标 | 含义 |
|---|---|
| `ic_abs` | 信息系数绝对值 |
| `icir` | IC 的信息比率 |
| `t20_ann` | 多头组合年化 |
| `t20_excess_ann` | 相对基准超额年化 |
| `t20_ir` | 超额的 IR = 超额年化 ÷ 跟踪误差 |
| `t20_rel_dd` | 最大相对回撤 |
| `top_ann` | 头部组合年化 |
| `monotonic` | 分层是否单调 |
| `time_slice_sensitivity` | 时间切片敏感性 |
| `monotonicity_v01` | 分层形态（非数值阈值） |
| `annual_decay_v01` | 年度衰减 |

**注意**：平台没有"夏普"，用 **IR**（对指增，绝对夏普被大盘 beta 主导、没信息量）。

### 5.2 评级阈值

| 检查项 | 优秀线 | 良好线 | 可软补偿 |
|---|---|---|---|
| `ic_abs` | ≥0.0500 | ≥0.0300 | ❌ |
| `icir` | ≥0.5000 | ≥0.3000 | ❌ |
| `t20_excess_ann` | ≥8.00% | ≥5.00% | ✅ |
| `t20_ir` | ≥1.00 | ≥0.60 | ❌ |
| `t20_rel_dd` | ≥−6.00% | ≥−12.00% | ✅ |
| `top_ann` | ≥12.0% | ≈8.8% | ❌ |
| `t20_ann` | 实操按 ≥10% | — | ✅ |
| `monotonic` / `time_slice_sensitivity` | 布尔硬门槛 | — | ❌ |
| `monotonicity_v01` / `annual_decay_v01` | 非数值阈值 | — | ❌ |

**判定**：硬门槛全过 + 非补偿项全达优秀 + 可补偿项最多 1 项未达 → 优秀。
**双窗都优秀**才有入库资格。

### 5.3 双窗（防过拟合的硬机制）

- P1：2017–2022。
- P2：2023–2026。
- **两窗都"优秀"才允许入库**。

### 5.4 实测规律（重要）

- 双窗优秀的配置**全部是"分行业"**，`5桶` 一个都没有（1306 行账本里 18 个）。
- `5桶` 的 P2 超额历史上限 **4.74**（＜优秀所需的 ~6.2）→ **靠改 5 桶压回撤方向本身就错**。
- 能用的是"分行业 + 信号自带低回撤"（18 个样本回撤都在 −8 以内）。
- 持有期 **5 日整体最优**（88 档统计：5日 61% > 10日 46% > 20日 26%）。

## 六、相似度系统（平台最值钱的部分）

### 6.1 规则

- 比对**审核那一刻正式库全部因子**，取最大 `|Spearman|`（日均截面，OOS 2023–2026）。
- 门槛：
  - 用了软补偿 → **0.40**；
  - 两窗四项策略指标全硬过（零软补偿）→ **0.60**。
- **ρ 只由因子值决定**，与回测配置（池/策略/持有期/变体）无关。

### 6.2 精确端点

```
POST /api/factors/{factor_id}/evaluation/similarity
→ similarity.max_abs_rho
→ similarity.top_peers[{peer_id, peer_name, abs_rho, window_days, ...}]
```

- 前提：因子必须已 `save_factor`（有值）。
- 已入库因子会匹配到自己（1.0），判断时排除。
- **客户端超时必须给 3000s**，否则永远算不完、服务端任务作废、`values_in_db` 恒 0。

### 6.3 两种预测方式

| 方式 | 用途 | 局限 |
|---|---|---|
| `sim_screen.py`（est#28 / est#24） | 建因子前粗筛，快 | 看不见 #18（资金流/大单类），会系统性高估 |
| `sim_exact.py` | 建因子后精确值 | 要建因子、要等 |

**推荐**：粗筛 → 有希望再 `save_factor` + 精确端点终审。

### 6.4 降相似度的手段（实测有效/无效）

| 手段 | 效果 |
|---|---|
| 加**振幅腿**（`ADD(RANK(基座), 0.15~0.25×RANK(振幅))`） | 反转族有效（0.414→0.319/0.359） |
| 换时间序列聚合（`TS_MEAN`→`TS_RANK`） | ρ 大降（0.416→0.182），但 alpha 也掉 |
| 混血（两腿相加） | **只对主对手是 #28/#31 的基座有效**；主对手是自家已入库因子的，腿救不了 |
| 换池 | **不改变 ρ**（只能救"策略捕获弱"，救不了"撞库"） |

## 七、入库与提交流程

### 7.1 提交流程

```
save_factor → sim_exact（ρ<阈值?）→ 回测 → 双窗优秀? → admit → 检查 submission_id
```

- `admit` payload 必须带 `confirm_no_window: true`（否则复合表达式**静默失败**，返回 ok 但 `submission_id=null`）。
- 还要带 `confirm_sensitivity: true`。
- **提交后必查 `submission_id` 非空**。

### 7.2 防重纪律

- **一个表达式终身只提交一次**（按表达式哈希查 `submitted.json`，不是 factor_id）。
- 同族第二条必须**等第一条审完再交**（#863/#875 互相 ρ=0.995，第二条被撤销）。
- 批量脚本里**不许**写自动 admit。

### 7.3 审核时长

随正式库规模增长：20 个因子时 15 分钟，100+ 因子时 **2~3 小时**。

## 八、平台硬约束（全部踩过）

1. `rebalance_horizon` 必须 10。
2. 变体只有 `raw/ma10/ma20/cap_neu`。
3. `top20_top_pct` 只认 10/20（且必须写在 `items[]` 里，body 级不生效）。
4. 持有期吸附到 `{1,5,10,20}`。
5. `admit` 必须带 `confirm_no_window: true`。
6. 长窗口（>252日）别走 batch，用 `runner.run(expression=...)`。
7. 批量接口的 `items[].expression` 覆盖不可靠 → 先 `save_factor` 再按 factor_id 跑。
8. 重复配置 → `skipped_dup`。
9. ICIR 由变体决定。
10. 别用 `exclude_st_future=True` + `min_list_days=250`（服务端报 `ModuleNotFoundError`）。

## 九、标准工作流

### 9.1 决策树（30 秒判断一个因子值不值得做）

```
新因子想法
├─ 机制是「短期反转/低换手/波动率」？→ 必然撞正式库，必须配正交腿
├─ 与纯低换手相关性 <0.35？→ 否：est≥0.40，别提交
├─ 基座换了吗？→ 只换附加腿 = 没换，ρ自库必 0.9+
├─ 能做出双窗优秀？→ 否：别提交
└─ 提交前跑 sim_screen，三轴（est#28 / est#24 / ρ自库）全 <0.40 才交
```

### 9.2 单次快筛（进 48 格之前）

**一条回测同时返回 h1/h5/h10/h20 的 IC、10 分层、逐年超额、全部硬门槛**，所以 1 条配置就能判生死。

**快筛判死条件（命中任一直接毙）**：
1. `max|IC| < 0.045`。
2. 分层呈 **U 形**（两头都差）。
3. `monotonic=Fail` 且 `time_slice_sensitivity=Fail`。
4. 逐年超额在 IS 前两年 ≈0（只是某段风格代理）。
5. **"头顶平坦、底部断崖"**（alpha 全在空头端，多头策略捕不到）。

## 十、故障排查

| 症状 | 先查什么 |
|---|---|
| 平台"卡了" | **先查 VPN**（`TAP-Windows Adapter V9` 是否 Up），再怀疑平台 |
| `similarity` 长连接断开 | 客户端 timeout 不够（要 3000s），不是平台过载 |
| `values_in_db` 恒 0 | 同上：similarity 任务被客户端断连作废 |
| `materialize` 返回 400 | 它是"入库动作"不是旁路，新因子不能绕过双窗 |
| `submission_id=null` | 没带 `confirm_no_window: true`，静默失败 |

## 十一、名词表

| 名词 | 含义 |
|---|---|
| 双窗 | P1（2017–2022）+ P2（2023–2026）两段都评估 |
| 软补偿 | `t20_ann / t20_excess_ann / t20_rel_dd` 三项可各放宽 1 项 |
| 零软补偿 | 两窗四项策略指标全硬过 → 相似度门槛 0.60 |
| 撞库 | 与正式库某因子 ρ ≥ 门槛 |
| 族封死 | 同机制因子已入库，后续变体必撞（ρ 0.9+） |
| est#28 / est#24 | 与 #28（低换手/反转）、#24（振幅）两条轴的预测相关 |
| ρ自库 | 与"正式入库"因子的日均截面 \|Spearman\|（精确值） |

## 十二、这套平台"值得抄"的四条设计

1. **相似度闸门**：提交前先算撞不撞，省的是审核资源，更是自己的时间。
2. **单次快筛**：1 条回测返回全部关键指标，把 48 格降到 1 条（省 47 倍算力）。
3. **全量网格**：不许用一条配置给因子判死刑。
4. **实验台账**：按哈希去重、保留失败与落选、一次表达式只交一次。
