# 使用 Argo 时发现的问题与改进

功能分类与当前状态见[项目功能清单](项目功能清单.md)。以下针对指定版本与使用路径：五类计算/账户问题，加一项收盘信号的成交模型扩展；不将它们笼统称为六个 bug。

这部分说明我们为什么检查平台实现，以及改动如何影响回测。已有修复在作者本机通过测试，后续还需按指定源码版本复跑。这里按问题归类，不把每次调试轮次当成一个新贡献。

| 问题 | 为什么会影响结果 | 已做的处理 | 复核时看什么 |
|---|---|---|---|
| 信号与成交在同一根日线 | 收盘后才知道的信号可能使用当根价格成交 | 加入可配置的 next-bar 市价单执行，下一根 Open 成交 | 当根不成交、下一根开盘定价、最后一根没有下一次成交；限价单仍有不同语义 |
| 可用余额没有及时同步 | 后续买单可能按旧现金计算，甚至出现负现金 | 成交后更新余额与 buying power | 同一开盘连续订单使用更新后的现金，买单不能透支 |
| 买入校验漏算手续费 | 成交金额没超余额，但加手续费后超额 | 买入预算包含费用，并在实际成交时再检查 | 含费不足和跳空后不足的订单被拒绝 |
| Equity 账户价值计算不一致 | 持仓账户的收益和风险统计可能错误 | 按现金加各币持仓市值计算并同步 | 两币持仓与共享账户，逐日净值对账 |
| EMA 读取历史过短 | 只读20根，初始化后没有递推，EMA20退化为简单均线 | 读取更长历史窗口，并保留不足历史时的回退规则 | EMA与SMA有差异；预热边界与独立实现一致 |
| 持仓浮点精度与截断 | 应卖0.09却因浮点残差只卖0.08，或容差过大导致超卖 | 修正取整与精度边界，增加回归测试 | 0.08999…残差、8/12位精度、略低于刻度的数量不能上取整 |

六项存在相互影响，所以不能把不同轮次的收益差分别相加。当前三案例均使用修复后的账本；收益、回撤和现金误差见三案例结果与复核说明。

## EMA20 的预热行为需要向使用者说明

当前实现每次请求最近 60 根历史。若不足 60 根，数据源返回错误，EMA 再请求最近 20 根。这时没有额外数据可以递推，数值就是这 20 根的简单平均；满 60 根后，从窗口前 20 根简单平均开始，使用后 40 根递推。

这项修复解决了“始终退化成简单均线”的问题，但有限窗口和早期回退仍是特定实现选择。它与从完整历史连续更新的 EMA 不完全相同。建议在平台文档中明确窗口长度、初始化方法、历史不足时是否允许交易，并用边界测试固定约定。若以后改成另一种初始化方法，应作为算法版本变化，重新回测并生成新审计包。

独立 Python 首版使用不足60根时的全部可用历史，得到392笔；按源码中的回退规则实现后，得到与Argo一致的390笔。这个过程说明“指标名称一样”并不保证计算细节一样。

## 对助教平台可提交的建议

将问题拆成独立 issue 或 PR，每条提供触发例子、预期结果、实际结果、修复及测试。优先建议公开说明成交时序与账户字段，并明确 EMA 初始化。官方 CI 已有 WASM 夹具构建与完整测试步骤；我们的工作是将新增专项回归接入现有流程，并核对实际修复版本和日志，不是首次建立 CI。

本项目里的独立重放证明了行情和所述规则可以产生与保存账本相同的交易；它不证明平台所有功能都正确。当前没有向助教仓库提交 issue 或 PR，后续如需提交，由两人整理证据后执行。
