# 功能范围与开发计划

项目定位：基于 Argo 的加密策略研究工具原型。三个固定策略是需求与验收案例，不以发现新 alpha 为目标。

## 区分基础能力、已做工作和待做功能

| 研究环节 | 当前依据 | 我们已做的事 | 计划补充 |
|---|---|---|---|
| 策略输入与执行 | 使用Argo的Go/WASM策略及配置、指标与回测机制 | 保存三案例配置和源码快照；独立Python验证 | 盘点现有入口，再选Python适配或受限表达式之一 |
| 信号检查 | 指标规则可从源码与独立实现检查 | 记录并复现EMA预热和Williams阈值 | 导出逐日指标值、买卖信号、无动作原因，按日期查看 |
| 成交与账户 | 原引擎账本 | 修正执行/现金/费用等问题，逐笔和逐日核对 | 在查看页关联信号、次日订单、成交、现金及持仓 |
| 结果分析 | 原平台有基础回测统计 | 补同口径共享账户、基准、状态、仓位及成本分析 | 提供可浏览的净值/回撤与实验对照，指标说明可查 |
| 实验记录 | 配置和结果文件 | v2包记录参数、数据与代码指纹、成交和净值 | 增加run_id、生成时间、变更说明与父实验关联，保留失败和落选试验 |
| 回测记录上链与核验（同学主导） | 同学已有合约工程在另一仓库 | 审计包、本地哈希演示和待接入脚本 | 接入Hardhat，提交包哈希并保存proof，读链验证原包通过/修改失败 |

这是一份已验证使用路径的盘点，不代表 Argo 缺少表中所有待做功能。实现前检查原项目的接口和界面；已有能力优先复用，并标明来源。

## 第一版优先完成

**P0：按日期检查研究过程。** 用MA60先走通，随后适配另外两个案例。选一个日期能看到币种、价格、指标值、阈值、信号和理由；如果次日成交，可跳到成交记录及现金/持仓变化。预热不足、没有信号和没有成交应能区分。当前还没有这套导出和交互页面，独立重放对齐不等于该功能完成。

**P0：记录和比较实验。** 每次运行有唯一编号，保存配置、数据和代码指纹、结果及说明。两次实验比较时，既展示绩效差异，也展示参数和成本变化。保留原始记录，修改产生新版本，不覆盖已有存证包。

**P0：回测记录上链与链上核验。** 这是平台正式功能，由同学主导：生成审计包 → 提交包哈希 → 保存交易凭据 → 读链验证 → 篡改失败演示。复用同学的合约工程，先在本地链完成一个案例闭环，再考虑测试网和批量提交。proof与包路径、哈希及网络关联。

**P1：策略输入接口。** Python适配和表达式不是同一个功能。先确定用户需要表达的是交易规则还是因子数值；明确可访问数据、信号时间、仓位和订单接口。第一版选择一个有限范围的入口；不能把独立Python参考实现叫作通用接入。

实时数据、实盘下单、复杂DSL、多链、代币化均不属于第一版承诺。

## 三案例如何验收功能

- MA60：能看清收盘产生信号、次日开盘成交；基准与现金/手续费口径清楚。
- EMA20：能查看预热状态，并解释为何不足60根与满60根的初始化不同。
- Williams14：能看到14日高低区间、%R值、−80/−20阈值及相应动作。
- 三者：都能比较收益、回撤、仓位和市场状态；都能追溯到实验配置与文件版本。

研究指标包括收益、风险、敞口和成本；产品验收更关注能否定位一个信号、复现一次实验、说明两次实验的差异并核验交付版本。不用高收益作为功能是否成功的验收标准。
