## 第一版优先完成

**P0：按日期检查研究过程（已交付 CLI 原型）。** `python final_project/inspect_case.py --case ma60 --day 2022-03-02` 输出该日两币的收盘价、指标值、持仓、信号与理由、次日成交及成交后现金；EMA20 会显示预热状态（SMA 回退 / 满 60 根递推）。三个案例均已适配。尚无交互页面，属于命令行原型。

**P0：记录和比较实验（基础 CLI 原型，需完善）。** `python final_project/run_record.py record` 记录案例配置、数据指纹与结果，`compare A.json B.json` 比较记录。当前代码提交号写死，相同输入写入同一路径可能覆盖；尚不能保证每次运行唯一、不可覆盖或真实构建追踪，不能称为完整实验管理系统。

**P0：回测记录上链与链上核验（已完成，2026-11-28 同步状态）。** Hardhat 已接入，三份 v2 包的文件指纹、网络、合约、交易回执和读链结果已逐项核对。三案例均完成原包通过、修改副本失败、原包再次通过，凭据位于 `proofs/chainlab/`，工程通过 PR #1 合入。见 [测试网结果](chainlab-results.md)。Qiyuan 跨电脑复查仍待确认；来源文件自动核验及 Argo 工程复核不能由整包链上验证替代。

**P1：策略输入接口。** Python适配和表达式不是同一个功能。先确定用户需要表达的是交易规则还是因子数值；明确可访问数据、信号时间、仓位和订单接口。第一版选择一个有限范围的入口；不能把独立Python参考实现叫作通用接入。

实时数据、实盘下单、复杂DSL、多链、代币化均不属于第一版承诺。

## 三案例如何验收功能

- MA60：能看清收盘产生信号、次日开盘成交；基准与现金/手续费口径清楚。
- EMA20：能查看预热状态，并解释为何不足60根与满60根的初始化不同。
- Williams14：能看到14日高低区间、%R值、−80/−20阈值及相应动作。
- 三者：都能比较收益、回撤、仓位和市场状态；都能追溯到实验配置与文件版本。

研究指标包括收益、风险、敞口和成本；产品验收更关注能否定位一个信号、复现一次实验、说明两次实验的差异并核验交付版本。不用高收益作为功能是否成功的验收标准。
