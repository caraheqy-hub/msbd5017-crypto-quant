## 一 我们完成了什么

审计包是一份实验档案，记录策略配置、数据和代码来源指纹、每笔交易、每天的账户价值。完整文件保存在项目中；区块链保存文件的 SHA-256 指纹、提交者和区块时间。

可以把存证合约理解为登记本，把 proof 凭据理解为查询小票。凭据告诉程序：到哪条链、哪个合约、哪条记录中核对文件。

```text
存证时：审计包 → 计算指纹 → 把指纹写入 chainlab → 保存凭据
核验时：当前文件 → 重新计算指纹 → 与凭据和链上记录比较
```

验证通过表示当前文件与存证时一致。回测计算是否正确需要测试和对账，不能由区块链指纹证明；历史结果也不能保证未来收益。

## 五 分别验证三个原文件

验证 MA60：

```powershell
$env:AUDIT_CASE = "ma60"

```

验证 EMA20：

```powershell

```

```powershell
$env:AUDIT_CASE = "williams14"
bun run chainlab:verify
```

每次预期看到：

```text
CHAINLAB VERIFICATION PASSED. Read-only; no transaction signed or sent.
```

含义是：当前文件指纹、凭据和链上存证匹配。程序也核对合约地址、网络、交易回执、区块及存证事件，不是只比较两份本地文件。

`AUDIT_CASE` 选择案例，脚本自动选择对应审计包和 `proofs/chainlab/<案例>.proof.json`。本地链脚本使用的 `AUDIT_PACKAGE`、`AUDIT_PROOF` 不影响这个入口。

快捷命令 `bun run chainlab:verify` 对应的完整指令是：

```powershell
bunx hardhat run scripts/verify-chainlab.ts --network chainlab
```

两种写法选择一种即可。

## 六 现场生成篡改副本

副本是为了测试人为制造的错误样本，不表示真实有人攻击过项目。下面在 `build/handoff-demo/` 中生成三份副本，只增加第一笔交易的数量，不修改原文件：

```powershell
@'
import json
from pathlib import Path

output = Path("build/handoff-demo")
output.mkdir(parents=True, exist_ok=True)
for case in ("ma60", "ema20", "williams14"):
    source = Path(f"final_project/cases/{case}/audit_package.json")
    obj = json.loads(source.read_text(encoding="utf-8"))
    before = obj["trades"][0]["qty"]
    obj["trades"][0]["qty"] = round(before + 0.01, 10)
    target = output / f"{case}.tampered.json"
    target.write_text(
        json.dumps(obj, ensure_ascii=False, indent=2) + "\n",
        encoding="utf-8", newline="\n"
    )
    print(case, before, "->", obj["trades"][0]["qty"], target)
'@ | python -
```

当前三案例的数量变化应为 MA60 `0.10 → 0.11`、EMA20 `0.10 → 0.11`、Williams14 `1.49 → 1.50`。重复执行只重新生成演示副本。

## 七 检测副本并切回原文件

MA60：

```powershell
$env:AUDIT_CASE = "ma60"
$env:AUDIT_VERIFY_FILE = "build/handoff-demo/ma60.tampered.json"
bun run chainlab:verify
```

预期出现下面的错误。它是测试成功的表现，不要因此重新上链：

```text
AUDIT VERIFICATION FAILED: file fingerprint mismatch
error: script "chainlab:verify" exited with code 1
```

可在失败命令之后立即输入 `$LASTEXITCODE`，应显示 `1`。这里表示程序明确拒绝了指纹不一致的副本。

然后切回原文件，预期通过：

```powershell
Remove-Item Env:AUDIT_VERIFY_FILE -ErrorAction SilentlyContinue
bun run chainlab:verify
```

EMA20 按同样顺序执行。下面两次验证之间，会先清除副本设置：

```powershell
$env:AUDIT_CASE = "ema20"
$env:AUDIT_VERIFY_FILE = "build/handoff-demo/ema20.tampered.json"
bun run chainlab:verify

Remove-Item Env:AUDIT_VERIFY_FILE -ErrorAction SilentlyContinue
bun run chainlab:verify
```

预期：第一次指纹不匹配、退出码 1；第二次通过。

Williams14：

```powershell
$env:AUDIT_CASE = "williams14"
$env:AUDIT_VERIFY_FILE = "build/handoff-demo/williams14.tampered.json"
bun run chainlab:verify

Remove-Item Env:AUDIT_VERIFY_FILE -ErrorAction SilentlyContinue
bun run chainlab:verify
```

预期同样是先失败、再通过。结束时清除副本设置，避免下一次误验副本。

## 十一 常见情况怎么看

| 情况 | 如何处理 |
| --- | --- |
| 原文件验证通过 | 与既有 chainlab 存证匹配 |
| 修改副本报指纹不匹配 | 预期结果；清除副本设置，再验证原文件 |
| 原文件也报指纹不匹配 | 先检查 `AUDIT_CASE` 和 `AUDIT_VERIFY_FILE`，再核对收到的原文件是否与凭据配套；不要直接重存证 |
| 找不到 proof 文件 | 交接时漏了 `proofs/chainlab/`，或案例名称选错；需要取得已有真实凭据 |
| 网络超时或连不上 | 检查网络连接及 chainlab 服务；这不代表文件篡改 |
| 网络起点不匹配或合约缺失 | 可能连错网络或测试网发生变化，保留现有证据并核查，不要绕过检查 |
| 验证时提示 keystore 密码 | 确认运行的是 `chainlab:verify`，不是账户或提交命令；只读入口已禁用账户加载 |
| 想再次演示上链 | 当前文件已存证，直接验证即可；不要为演示重复提交相同文件 |

测试网可能重置，不能把它当作永久文件存储。保留文件、凭据和验证证据，比只保存交易编号更完整。
