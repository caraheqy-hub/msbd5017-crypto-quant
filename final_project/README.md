# 三个候选策略：怎样运行和阅读

我们用 MA60 作均线入门案例，EMA20 作较快的趋势对照，Williams14 作区间位置信号对照。每个策略单独回测 BTC/ETH，共享初始现金 10000 USDT。策略之间没有合并资金。

先看[三案例结果表](cases/three_cases.md)：包括全期收益、回撤、相对基准收益差，以及各市场状态的仓位、价格和费用贡献。表格由脚本生成，不手工填写数字。

## 一条命令重建

从仓库根目录运行：

```powershell
python -m pip install -r requirements.txt
python final_project/build_cases.py
```

脚本使用仓库里的原始成交文件，保留同时间戳内的成交顺序，逐笔核对现金、手续费和成交开盘价，再重建每日净值。随后为三个案例运行相同的市场状态分析，生成结果表。任何核对失败都会停止。

这能复算成交之后的账户变化，尚未重跑 Argo 引擎或独立生成 EMA20/Williams14 信号。MA60 此前有独立 Python 参考实现对账；另外两个策略仍需补上这一层验证。

## 基准与超额收益

基准是最初资金 BTC/ETH 各半、首日开盘扣除 0.1% 买入费、之后持有。它是自建基准，不是正式指数，权重会随价格漂移。策略成交同样按每边 0.1% 计费。

结果表同时列“策略累计收益减基准累计收益”（百分点），以及“策略期末财富除以基准期末财富再减一”。两个值含义不同，均不能直接叫风险调整后的 alpha。分状态另列策略与基准的平均日收益差。

## 市场状态与敞口怎么读

当天用前一天已知的 BTC 过去 30 天涨跌划分状态：超过 +10% 为上涨，低于 −10% 为下跌，其余震荡。前 31 天不分类。因此“下跌”指近期下跌后的交易日，不是完整熊市；基准在这些日子可能出现反弹。

开盘有效敞口是开盘成交后持仓市值除以上日净值。单位敞口指标用状态内每日收益或费用之和，除以每日敞口之和；分母很小时数值会放大。它能帮助理解仓位和成本，但不同币种权重和择时仍混在其中，不是纯信号效应。

## 审计包版本

`cases/` 的 v2 包补入了指标、仓位参数和来源文件哈希，完整文件哈希与根目录 `audit/` 的 MA60 v1 包不同。重建后的 MA60 成交及净值 Merkle root 应仍与原包一致。三份 v2 包均未上链。

引擎提交号在新包中标为历史记录所报版本，尚未从该提交在本仓库重新运行。保存源码和配置快照有助于追溯，但不等于已证明它们生成了原账本。下一步由 PR 2 补齐引擎版本和独立信号复核。
