# Qiyuan 的两分钟部分：研究工具方向

配套：`group27_interim_qiyuan_2min.pptx`，三页英文。约229词，按每分钟115–125词并留少量停顿，约两分钟。每页PPT备注也有英文稿。同学接第四页，用一分钟介绍记录的外部核验和上链进度；全组只上传合并后的一份。

## 第1页：使用者与研究痛点（约35秒）

Our project supports crypto researchers who need to explain and review a strategy experiment. A return curve does not explain why a trade happened, what changed between runs, or whether another person can reproduce the result. We are building a research toolkit on Argo, connecting rule execution, analysis and experiment records. The three strategies are examples for testing this workflow, rather than investment recommendations.

中文提示：用具体研究任务引出工具价值。用户不只看收益，还要解释交易、比较实验和交付复核。三个策略是演示案例。

## 第2页：解决方案与功能范围（约45秒）

A researcher first defines rules, then checks signals and trades, compares results, and saves the experiment. Argo provides the execution foundation. We have added account checks, independent Python replay, and common analysis of benchmarks, market conditions, exposure and costs. MA60 tests simple rules, EMA exposes initialization details, and Williams tests thresholds. Next, we plan to connect indicators and fills by date, and make experiment versions easier to compare. General Python input and expressions are proposed options; they are not implemented yet.

中文提示：按研究流程讲表格，分清当前脚本与计划新增功能。不要展开指标公式或收益排名。Python独立重放已经完成，通用Python策略接入还没有完成；二者不同。

## 第3页：进展、下一步与交接（约40秒）

Our current prototype uses scripts and files. We corrected execution and account issues, and independently reproduced all 730 trades from prices and rules. Each example also has an audit package containing configuration, file hashes, trades and daily account value. Next we will prioritize signal inspection and experiment tracking, while reviewing the Argo build and integrating the blockchain component. We would welcome feedback on which research step matters most. My teammate will now explain how reviewers can verify the delivered record’s version.

中文提示：730=168+390+172，表示交易计算复现，不是730次盈利验证。先说明当前是脚本原型，再讲待做的查看与记录功能。最后交给同学讲存证，不替她展开实现。
