## 需修正或补证据

1. **限价单根因仍是高可信假设，不是闭环证明。** 原套件 `testRunner` 的确只清数据库而复用交易对象，因此存在隔离风险；但紧前一个子用例的 `pendingOrderNumber=0` 断言通过。新的独立测试 PASS 只说明同样的行情和限价单在干净状态下工作，不能确认原测试里那笔成交的订单来源。建议运行原失败子用例的完整路径过滤测试，或在原 `testRunner` 记录入场 pending、入场订单表、`UpdateCurrentMarketData` 后队列、意外成交的 OrderID/价格/时间；随后仅对 `testRunner` 做局部独立实例改造，并以原套件从 FAIL 到 PASS 作为闭环证据。
2. **测试数量写错。** `nextbar_causality_test.go` 现有 **11 个** `Test...` 方法：前九个加 `TestHighPrecisionNoOverSell`、`TestLimitBuyOutOfRangeStaysPending`。文档第五节写“12 个，全部 PASS”应改成 11 个；“原有断言”不是第十二个测试。
3. **高精度测试仍有限。** 8 位精度测了略低于刻度的真值；12 位只测了恰好落在刻度上的数，没有测“12 位真实低于刻度不得上取整”。也没有用真实持仓和卖单路径检验 8/12 位不超卖。建议补这两类边界；通用 `float64` 数量在 12 位精度附近仍值得谨慎，不宜只凭当前单测声明全精度安全。
4. 文档只给出 WSL 与 Windows SHA-256 的首尾摘要，未附两侧完整命令输出。我在当前 Windows 环境无法进入 WSL（此前返回 `WSL/E_ACCESSDENIED`）；因此**未独立核实 SHA 一致**。下轮日志应保存两个完整哈希和运行时 Git 提交号。
