## 一、项目定位

课程给的题目是 **Blockchain-Anchored Multi-Strategy Back-testing & Execution**。目前两边各自只覆盖了一半：

| | 组员（group27_trade） | 我们（crypto_project / Argo） |
|---|---|---|
| 覆盖 | 链上存证 + 单策略 + 三段行情 | **多策略** + 平台缺陷修复 + 参考实现对齐 |
| 强项 | 合约、上链/验证脚本、数据管道、结果证明 | 7 策略回测、逐笔对账、前视偏差与账户语义研究 |
| 缺口 | 只有单策略，锚定对象只有"最终 JSON" | 没有链上锚定 |

**收敛点**：题目里的 **Multi-Strategy** 由我们补，**Anchoring** 由组员补，**研究贡献**用我们发现的平台缺陷来立住。

## 二、一句话主线

> 不只把"最终收益"锚上链，而是把**参数 + 数据版本 + 逐笔成交 + 每日 NAV** 的完整审计记录锚上链；并用一次真实的平台缺陷修复证明——**没有审计锚定，回测收益不可信**。

## 三、三层结构（由浅入深，全部可交付）

### 第 1 层：基础存证（组员已完成，直接复用）
- 单策略 × 牛/熊/震荡 → 结构化 JSON → SHA-256 → `BacktestRegistry.anchorBacktest()` → 验证/篡改演示。
- 已有：`contracts/BacktestRegistry.sol`、`scripts/anchor-*.ts`、`verify-backtest.ts`、`results/regimes/*.proof.json`。

### 第 2 层：审计级锚定（新增，工作量可控）
把锚定对象从"一个 JSON 的哈希"升级为**审计包**：

```
audit_package = {
  config:   策略参数、手续费、next_bar_execution 等,
  data:     BTC/ETH 日线的 SHA-256,
  trades:   168 笔逐笔成交的 Merkle root,
  nav:      每日 NAV 序列的 Merkle root,
  reference: 独立 Python 参考实现的哈希
}
→ 只把 audit_package 的 SHA-256/Merkle root 上链
```

合约只需加一个方法（现有 `anchorBacktest(bytes32)` 已够用，或加 `anchorAudit(bytes32 root, string meta)`）。

### 第 3 层：研究贡献（我们的核心资产）
在 Argo Trading 平台上复现并修复 **6 类缺陷**，量化其对收益的影响：

| 缺陷 | 影响 |
|---|---|
| 同 bar 前视（信号与成交同一根） | MA60 从 +40.6% 虚高 |
| 挂单买入绕过余额检查 | 可透支 |
| EMA 预热窗口不足（EMA20≡MA20） | 指标退化 |
| 余额从不回写（`getBuyingPower` 恒 10000） | 3 天负现金，最低 −2475 |
| 买入校验漏手续费 | 可超额买入 |
| 持仓浮点截断（0.0899…→0.08） | 少卖 0.01 BTC |

修复后 MA60 共享账户 **+114.28%**（修复前虚高 +117.9%），独立参考实现逐笔对齐误差 **≤1.46e-11**。

**这张表就是"为什么需要审计锚定"的实证**：同一个策略、同一份数据，平台实现不同，收益差 3.6 个百分点；不锚定逐笔成交，外部无法发现。
